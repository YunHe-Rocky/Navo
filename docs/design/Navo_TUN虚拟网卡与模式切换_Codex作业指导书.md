# Navo 虚拟网卡生命周期与模式切换作业指导书

> 适用对象：Codex / 开发智能体  
> 适用范围：Navo Windows 客户端的“不托管 / 系统代理 / TUN”模式、代理内核进程、Navo 虚拟网卡、路由与 DNS 管理  
> 目标：建立明确的状态机、异常恢复机制和可验证的模式切换流程，避免虚拟网卡残留、内核空跑、路由污染及持续丢包。

---

## 1. 任务目标

本次开发必须完成以下行为：

1. **Navo 虚拟网卡仅服务于 TUN 模式。**
   - 未启用 TUN 时，不创建 Navo 虚拟网卡。
   - 从 TUN 切换到系统代理或不托管后，必须停止 TUN、释放路由和 DNS，再按产品策略删除虚拟网卡。
   - 软件启动时若当前模式不是 TUN，但检测到 Navo 残留网卡、残留路由或残留 DNS，必须执行清理。

2. **Navo 虚拟网卡被用户手动禁用、卸载或发生不可用时，软件必须立即响应。**
   - 立刻停止当前代理内核，不能允许内核继续以“已启动”状态空跑。
   - UI 弹出明确提示，并把运行状态切换为“异常停止”。
   - 再次启动 TUN 时，如果网卡缺失、被禁用或驱动状态异常，必须先恢复网卡，再启动内核。
   - 网卡恢复失败时，内核不得启动。

3. **不托管、系统代理、TUN 三种模式切换必须使用事务化流程。**
   - 禁止直接同时修改多个开关。
   - 禁止旧模式未完全退出就启动新模式。
   - 必须具备串行锁、超时、健康检查、失败回滚和启动恢复。
   - 不得承诺绝对零丢包；必须将短暂网络抖动限制在可控范围内，并保证不会产生持续断网、路由残留或 DNS 污染。

---

## 2. 术语定义

| 名称 | 定义 |
|---|---|
| `Unmanaged` | 不托管模式。Navo 不修改系统代理、路由、DNS，不运行代理内核。 |
| `SystemProxy` | 系统代理模式。运行内核并设置 Windows 系统代理，不创建虚拟网卡。 |
| `Tun` | TUN 模式。运行内核、创建并启用 Navo 虚拟网卡、配置路由和 DNS。 |
| `Core` | sing-box、Mihomo/Clash、Xray 等当前选中的代理内核进程。 |
| `Navo Adapter` | Navo 管理的虚拟网卡，只允许在 TUN 模式存在并参与工作。 |
| `DesiredMode` | 用户希望进入的模式。 |
| `ActualState` | 当前系统真实状态，必须通过进程、网卡、路由、DNS共同判断，不能只读 UI 变量。 |
| `Transition` | 从一种模式切换到另一种模式的完整事务。 |

## 3. 强制设计原则

### 3.1 单一状态源

不得分别用多个布尔值表示：

```text
isCoreRunning
isTunEnabled
isSystemProxyEnabled
isAdapterCreated
```

这种设计容易产生互相矛盾的组合。

必须建立统一运行状态，例如：

```text
Stopped
StartingSystemProxy
RunningSystemProxy
StartingTun
RunningTun
Stopping
Recovering
Faulted
```

并独立保存：

```text
DesiredMode = Unmanaged | SystemProxy | Tun
```

UI 展示必须来源于状态机，不允许 UI 开关自行决定真实运行状态。

### 3.2 单通道控制

所有以下操作必须通过同一个 `ModeTransitionCoordinator` 或等价组件执行：

- 用户点击启动、停止；
- 用户切换不托管、系统代理、TUN；
- 虚拟网卡被禁用、卸载；
- 内核异常退出；
- 软件启动后的环境修复；
- Windows 睡眠、唤醒、网络变化；
- 软件退出和系统关机。

任何页面、按钮、托盘菜单都不得直接调用“启动内核”“创建网卡”“设置系统代理”等底层方法。

### 3.3 串行化

模式切换必须加全局异步互斥锁。

同一时间只能存在一个启动、停止、恢复或切换事务。重复点击必须合并、忽略或取消前一个请求，不能并发执行。

## 4. Navo 虚拟网卡生命周期规范

### 4.1 创建条件

只有同时满足以下条件，才允许创建或恢复 Navo 虚拟网卡：

1. `DesiredMode == Tun`；
2. 当前切换事务持有全局模式锁；
3. 当前旧模式已经完成退出；
4. 代理内核尚未进入对外可用状态；
5. 驱动文件和权限检查通过。

未启用 TUN 时，禁止“提前创建”“后台预热”或“为了检测方便保留”虚拟网卡。

### 4.2 网卡唯一标识

不得只按显示名称匹配网卡。

至少使用以下一种稳定标识：

- 驱动实例 ID；
- PnP Device Instance ID；
- 自定义硬件 ID；
- 创建时持久化的 Adapter GUID；
- 驱动提供的唯一标识。

显示名称“navo”只能用于 UI，不得作为唯一判断依据。

### 4.3 网卡状态分类

必须把网卡检测结果规范化为：

```text
Missing
Disabled
Enabled
Starting
Stopping
DriverError
Unknown
```

禁止只返回 `true/false`。

### 4.4 非 TUN 状态清理

当目标模式为 `Unmanaged` 或 `SystemProxy` 时：

1. 停止接收 TUN 流量；
2. 停止内核；
3. 删除 Navo 添加的默认路由、分流路由和策略路由；
4. 恢复 Navo 修改的 DNS；
5. 删除或禁用 Navo 虚拟网卡；
6. 验证系统不存在 Navo 残留路由和 DNS；
7. 再进入目标模式。

清理逻辑必须具有幂等性：重复执行不会报错，也不会误删非 Navo 创建的配置。

## 5. 用户手动禁用或卸载虚拟网卡

### 5.1 监听方式

必须监听 Windows 设备变化事件，并保留低频兜底轮询。

推荐组合：

- Windows 设备通知、WMI 或 Configuration Manager 事件；
- SetupAPI / NetAdapter 查询用于确认真实状态；
- TUN 运行期间每 2～5 秒执行一次轻量健康检查，防止事件丢失。

不得只依赖 UI 定时器，也不得每秒执行昂贵的全量设备扫描。

### 5.2 触发条件

当前处于 `StartingTun` 或 `RunningTun` 时，出现以下任一情况，视为严重故障：

- Navo 网卡被禁用；
- Navo 网卡被卸载；
- 网卡 GUID 变化且旧实例消失；
- 驱动错误；
- 网卡无法获取预期地址；
- Navo 必需路由消失；
- 内核 TUN 入站监听失败。

### 5.3 故障处理顺序

必须严格执行：

1. 原子地把运行状态切换为 `Faulted` 或 `Recovering`；
2. 禁止继续接受新的启动或模式切换请求；
3. 立即停止代理内核；
4. 清理系统代理、路由和 DNS 中由本次运行创建的内容；
5. 记录故障原因、设备状态、内核退出码和清理结果；
6. 弹窗提示用户；
7. UI 显示“虚拟网卡异常，内核已停止”；
8. 当前模式不得继续显示为“运行中”。

建议弹窗文案：

> 检测到 Navo 虚拟网卡已被禁用、卸载或异常，代理内核已自动停止。重新启动 TUN 时，Navo 将尝试恢复虚拟网卡。

禁止在网卡失效后让内核继续运行并只显示黄色警告。

### 5.4 防止重复弹窗

同一次故障只弹一次。

可以使用：

```text
faultFingerprint = faultType + adapterInstanceId + transitionId
```

在状态恢复或用户重新启动后清除该指纹。

## 6. 再次启动 TUN 时的自动恢复

启动 TUN 前必须执行以下预检：

1. 检查管理员权限；
2. 检查驱动文件；
3. 检查 Navo 网卡状态；
4. 检查残留路由和 DNS；
5. 检查端口占用；
6. 检查旧内核进程；
7. 检查上一次非正常退出标记。

按网卡状态处理：

| 状态 | 处理 |
|---|---|
| `Missing` | 创建新网卡，等待系统枚举完成。 |
| `Disabled` | 启用网卡并等待状态变为可用。 |
| `Enabled` | 继续校验地址、MTU、驱动版本和绑定关系。 |
| `DriverError` | 尝试重新安装或重建一次；仍失败则停止启动。 |
| `Unknown` | 不允许启动内核，返回明确错误。 |

恢复顺序：

```text
清理旧状态
→ 创建/启用网卡
→ 等待网卡 Ready
→ 配置地址与 MTU
→ 生成内核配置
→ 启动内核
→ 等待内核健康
→ 写入路由
→ 写入 DNS
→ 连通性检测
→ 标记 RunningTun
```

**核心要求：网卡未恢复成功之前，不得启动内核；内核未健康之前，不得写入最终默认路由。**

## 7. 三种模式切换事务

### 7.1 标准切换流程

所有模式切换统一执行：

```text
Acquire transition lock
→ Set state = Stopping/Starting
→ Stop old mode
→ Verify old mode is fully cleaned
→ Prepare target mode
→ Start target mode
→ Health check
→ Commit state
→ Release lock
```

### 7.2 不托管 → 系统代理

1. 清理残留 TUN 路由、DNS、网卡；
2. 启动内核；
3. 等待本地代理端口可用；
4. 保存当前系统代理原值；
5. 设置系统代理；
6. 执行连通性检测；
7. 进入 `RunningSystemProxy`。

### 7.3 不托管 → TUN

1. 清理残留系统代理；
2. 恢复或创建虚拟网卡；
3. 启动内核；
4. 等待 TUN 入站和网卡就绪；
5. 写入路由和 DNS；
6. 连通性检测；
7. 进入 `RunningTun`。

### 7.4 系统代理 → TUN

1. 先保持旧内核运行，但阻止新请求进入切换流程；
2. 清除系统代理设置并恢复原值；
3. 停止旧内核；
4. 验证端口释放；
5. 创建或恢复虚拟网卡；
6. 使用 TUN 配置重新启动内核；
7. 写入路由和 DNS；
8. 验证 TUN 连通性；
9. 进入 `RunningTun`。

禁止在同一个内核进程中热修改到 TUN，除非当前内核明确提供可靠、可回滚的原子重载能力，并经过专项测试。

### 7.5 TUN → 系统代理

1. 先阻止新的切换请求；
2. 删除默认路由和分流路由；
3. 恢复 DNS；
4. 停止 TUN 内核；
5. 删除或禁用 Navo 网卡；
6. 验证网络已恢复到系统原始出口；
7. 使用系统代理配置启动内核；
8. 等待本地代理端口健康；
9. 设置系统代理；
10. 进入 `RunningSystemProxy`。

### 7.6 任意模式 → 不托管

1. 清除系统代理；
2. 删除 Navo 路由；
3. 恢复 DNS；
4. 停止内核；
5. 删除或禁用 Navo 网卡；
6. 验证无 Navo 进程、网卡、路由、DNS残留；
7. 进入 `Stopped`。

## 8. 丢包与网络中断控制

模式切换涉及默认路由、DNS 和网络栈变化，无法保证所有已有 TCP/UDP 会话绝对无损。实现目标应是：

- 不出现持续断网；
- 不出现错误默认路由；
- 不出现旧 DNS 长期残留；
- 不出现内核已停止但流量仍被导向虚拟网卡；
- 不出现虚拟网卡已删除但默认路由仍指向该网卡；
- 切换完成后新连接必须稳定可用。

必须采用以下措施：

1. 先撤销旧模式流量入口，再停止旧内核；
2. 新模式未健康前，不提交最终路由和系统代理；
3. 路由、DNS、系统代理修改必须记录前值；
4. 每一步设置超时；
5. 任一步失败立即进入回滚；
6. 切换完成后至少执行：
   - 本地端口检查；
   - DNS 解析检查；
   - 默认出口检查；
   - HTTP/HTTPS 连通性检查；
7. 快速连续点击模式按钮时，只执行最后一次有效目标模式；
8. 模式切换期间 UI 禁止重复操作，并显示具体阶段，而不是一直显示“启动中”。

## 9. 回滚规则

### 9.1 启动系统代理失败

1. 清除本次设置的系统代理；
2. 恢复原系统代理；
3. 停止内核；
4. 状态进入 `Faulted`；
5. 不保留虚假“已连接”状态。

### 9.2 启动 TUN 失败

1. 删除本次写入的路由；
2. 恢复 DNS；
3. 停止内核；
4. 删除或禁用本次创建的网卡；
5. 尝试恢复系统正常直连；
6. 状态进入 `Faulted`。

### 9.3 从 TUN 切换到系统代理失败

优先保证系统能够正常直连，不要强行恢复到一个状态不明确的 TUN。

回滚优先级：

```text
系统可联网
> 配置一致
> 恢复旧模式
> 保持用户选择
```

## 10. 启动恢复与崩溃恢复

软件每次启动必须执行环境审计：

1. 查找 Navo 遗留内核进程；
2. 查找 Navo 虚拟网卡；
3. 查找 Navo 写入的路由；
4. 查找 Navo 修改的 DNS；
5. 查找 Navo 修改的系统代理；
6. 读取上一次运行事务日志；
7. 判断上一次是否非正常退出。

恢复规则：

- 当前配置目标不是 TUN：清理 Navo 网卡、TUN 路由和 DNS。
- 当前配置目标是 TUN，但软件未自动连接：只修复残留，不自动启动。
- 用户主动点击启动 TUN：执行完整预检和网卡恢复。
- 发现状态无法判定：进入安全直连状态，不自动猜测。

建议持久化 `TransitionJournal`：

```text
transitionId
fromMode
toMode
currentStep
createdAdapterId
addedRouteIds
dnsBackup
systemProxyBackup
coreProcessId
startedAt
committed
```

事务成功后标记 `committed=true`。启动时发现未提交事务，按日志反向清理。

## 11. 组件职责建议

Codex 必须先阅读现有项目结构，再按当前技术栈落地。不要为了本任务大规模重写无关代码。

建议职责拆分：

```text
ModeTransitionCoordinator
  负责状态机、串行锁、事务、回滚

CoreProcessManager
  负责内核启动、停止、退出监听、健康检查

VirtualAdapterManager
  负责创建、删除、启用、禁用、状态检测

DeviceChangeMonitor
  负责监听网卡禁用、卸载、驱动异常

RouteManager
  只管理带 Navo 标记或由事务记录的路由

DnsManager
  负责备份、设置、恢复 DNS

SystemProxyManager
  负责备份、设置、恢复 Windows 系统代理

ConnectivityHealthChecker
  负责端口、DNS、出口和网络连通性检查

TransitionJournalStore
  负责崩溃恢复和操作审计
```

每个组件必须支持取消令牌、超时和幂等调用。

## 12. 日志要求

所有模式切换日志必须带：

```text
transitionId
requestedMode
previousMode
actualState
step
adapterInstanceId
corePid
elapsedMs
result
errorCode
```

重要日志：

- 网卡创建、启用、禁用、卸载；
- 网卡事件来源；
- 内核启动参数摘要；
- 内核退出码；
- 系统代理前值和恢复结果；
- 路由增加、删除结果；
- DNS 前值和恢复结果；
- 健康检查结果；
- 回滚的每一步；
- 弹窗是否已展示。

日志中禁止记录订阅密钥、代理密码、完整认证 URL。

## 13. UI 交互规范

### 13.1 状态显示

禁止只显示“已开启/已关闭”。

至少支持：

```text
未运行
正在停止旧模式
正在恢复虚拟网卡
正在启动内核
正在配置路由
正在检测连接
运行中
异常停止
正在回滚
```

### 13.2 异常弹窗

网卡被手动禁用或卸载时：

- 立即弹窗；
- 明确说明内核已停止；
- 提供“重新启动 TUN”和“关闭”；
- 点击重新启动必须走完整恢复流程，不得只执行 `EnableAdapter()`。

### 13.3 防抖

模式切换按钮触发后立即锁定，直到事务提交或回滚完成。

## 14. 测试要求

### 14.1 单元测试

必须覆盖：

1. 状态机合法和非法迁移；
2. 重复停止的幂等性；
3. 重复清理路由和 DNS；
4. 网卡 `Missing/Disabled/Enabled/DriverError` 分支；
5. 内核异常退出；
6. 切换中再次点击其他模式；
7. 各步骤超时；
8. 回滚失败后的安全状态。

### 14.2 集成测试

至少覆盖：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| T01 | 启动软件但不启用 TUN | 不存在 Navo 虚拟网卡。 |
| T02 | 不托管 → TUN | 创建网卡，内核和路由健康后进入运行中。 |
| T03 | TUN → 系统代理 | TUN 路由、DNS和网卡被清理，系统代理正常。 |
| T04 | 系统代理 → TUN | 系统代理被恢复，TUN 正常启动。 |
| T05 | TUN 运行时手动禁用网卡 | 内核立即停止，弹窗只出现一次。 |
| T06 | TUN 运行时手动卸载网卡 | 内核立即停止，路由和 DNS 被清理。 |
| T07 | 网卡禁用后重新启动 TUN | 网卡自动启用，成功后才启动内核。 |
| T08 | 网卡卸载后重新启动 TUN | 自动重建网卡，成功后才启动内核。 |
| T09 | 创建网卡失败 | 内核不启动，系统保持可直连。 |
| T10 | 内核启动失败 | 路由不提交，网卡和 DNS按规则清理。 |
| T11 | 切换过程中强制结束 Navo | 重启后自动清理未提交事务。 |
| T12 | 连续切换 100 次 | 无残留进程、网卡、路由、DNS和系统代理。 |
| T13 | 睡眠后唤醒 | 状态重新校验，不出现假运行。 |
| T14 | Windows 网络适配器变化 | 不误判其他网卡为 Navo 网卡。 |
| T15 | 无管理员权限启动 TUN | 明确失败，内核不启动。 |

### 14.3 网络稳定性测试

每次模式切换期间持续执行：

```text
ping 默认网关
ping 公共 IP
DNS 查询
HTTPS 请求
```

验收要求：

- 不允许持续断网超过 3 秒；
- 不允许切换完成后仍存在错误默认路由；
- 不允许 DNS 长时间指向已失效接口；
- 不允许 UI 显示运行中但内核或网卡实际不可用；
- 现有长连接可能重建，但新连接必须在切换完成后恢复。

## 15. 禁止实现方式

Codex 不得采用以下方案：

1. 用多个无约束布尔值拼接运行状态；
2. 每个 UI 按钮直接调用底层网络操作；
3. 网卡失效后只弹警告、不停止内核；
4. 网卡缺失时先启动内核再尝试创建网卡；
5. TUN 关闭后保留虚拟网卡用于“下次更快启动”；
6. 只按网卡显示名称识别 Navo 网卡；
7. 删除所有默认路由或修改所有网卡 DNS；
8. 切换失败后仍把按钮显示为已开启；
9. 使用固定延时替代状态确认；
10. 捕获异常后静默忽略；
11. 在没有回滚设计的情况下热切换内核配置；
12. 为修复此问题重写整个项目或改变无关业务行为。

## 16. Codex 实施顺序

Codex 必须按以下顺序执行：

### 阶段一：代码审计

先输出：

1. 当前模式状态存储位置；
2. 内核启动、停止入口；
3. TUN 网卡创建、删除入口；
4. 路由、DNS、系统代理修改位置；
5. UI 模式切换调用链；
6. 当前是否存在并发切换风险；
7. 当前是否存在网卡残留和内核空跑风险。

未完成审计前，不允许直接修改。

### 阶段二：状态机与协调器

先建立统一状态机和模式切换协调器，再迁移 UI 调用。

### 阶段三：网卡生命周期

实现网卡稳定识别、状态检测、创建、启用、删除和设备事件监听。

### 阶段四：事务与回滚

实现切换日志、超时、取消、回滚和启动恢复。

### 阶段五：UI 与提示

接入运行阶段、异常弹窗、防重复点击和错误信息。

### 阶段六：测试

补齐单元测试和集成测试脚本，执行完整模式切换矩阵。

## 18. 最终验收标准

仅当同时满足以下条件，任务才算完成：

- 非 TUN 模式不存在 Navo 虚拟网卡；
- TUN 网卡被禁用或卸载后，内核立即停止；
- 故障发生后 UI 不再显示运行中；
- 再次启动 TUN 时可自动恢复或重建网卡；
- 网卡恢复失败时内核绝不启动；
- 三种模式切换通过统一状态机和串行事务执行；
- 切换失败可回滚到安全直连状态；
- 软件崩溃或强制退出后可清理残留；
- 连续切换测试无进程、网卡、路由、DNS和系统代理残留；
- 所有关键逻辑有结构化日志和自动化测试；
- 不依靠固定等待时间猜测网卡、内核或网络是否已就绪。
