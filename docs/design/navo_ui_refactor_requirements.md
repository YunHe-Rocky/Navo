# Navo UI 重构与状态图标需求说明

## 1. 项目定位

Navo 是一款面向 Windows 的多内核代理管理工具，核心能力包括：

- 管理机场订阅节点；
- 管理独享代理、静态住宅代理或其他代理线路；
- 支持 sing-box、Mihomo、Xray 等内核；
- 支持系统代理、TUN 等流量接管方式；
- 展示连接状态、出口信息、实时流量、节点质量和诊断信息；
- 后续可能扩展到 Android 平台。

本次调整不是简单修改颜色或卡片，而是重新梳理：

1. 软件状态图标；
2. 运行概览信息；
3. 实时流量监控；
4. IP 检测与纯净度；
5. 页面职责和业务逻辑。

---

## 2. 当前界面问题

当前“运行概览”页面同时承担了以下职责：

- 选择代理内核；
- 选择线路来源；
- 选择流量接管方式；
- 显示运行状态；
- 显示出口 IP；
- 显示上传下载累计值；
- 显示配置版本和 PID。

这些功能被放在同一页面后，会让页面看起来像一个 `01 → 02 → 03` 的操作向导，但实际上：

- 内核不是每次连接都必须由用户手动选择；
- 线路来源和流量接管方式属于连接配置；
- 运行概览应该主要负责展示当前状态；
- 内核管理属于底层技术配置；
- IP 检测、流量监控和纯净度属于独立监控能力。

因此需要重新拆分页面职责。

# 3. 状态图标需求

## 3.1 不要把图标设计写死

不要直接固定使用某个具体图形、字母、配色或最终图标文件。

应先查看我当前 Navo 的 EXE 图标，并基于以下两种方向给出方案：

### 方向 A：沿用现有 EXE 图标

- 保留现有图标的品牌识别；
- 优化细节、清晰度、层次和小尺寸显示效果；
- 通过背景色、描边、发光、状态角标等方式表达不同运行状态；
- 不要破坏原有图标的整体识别度。

### 方向 B：重新生成新图标

如果现有图标不适合表达产品定位，可以重新生成一套图标方案。

新图标应符合 Navo 的功能定位：

- 网络控制；
- 代理连接；
- 路由切换；
- 多内核管理；
- 安全、稳定、可控；
- 现代 Windows 桌面软件；
- 技术感，但不要像廉价 VPN、杀毒软件或游戏加速器；
- 在 16×16、24×24、32×32、48×48、256×256 等尺寸下都能识别；
- 适合作为 EXE、任务栏、开始菜单和系统托盘图标。

在正式替换前，先给出 3～5 个图标方向或视觉方案，由我确认后再确定最终图标。

## 3.2 图标状态

图标至少需要表达以下四种运行状态：

| 状态 | 含义 | 建议视觉方向 |
|---|---|---|
| 默认状态 | 未启动代理或内核未运行 | 保持默认品牌外观 |
| 机场订阅代理正常 | 当前使用机场订阅节点，且出口检测正常 | 紫色系状态 |
| 独享代理正常 | 当前使用独享代理、静态住宅代理或普通代理线路，且出口检测正常 | 绿色系状态 |
| 代理异常 | 代理已启动，但连接、出口或可用性检测失败 | 红色系状态 |

注意：

- 图标的具体造型不要提前写死；
- 默认状态不强制改变背景；
- 紫色、绿色、红色主要用于表达状态；
- 可以使用背景、描边、发光、角标或状态点；
- 不一定必须整张图标完全变色；
- 红色异常状态优先级最高；
- 避免因短暂网络抖动导致图标频繁闪烁。

## 3.3 状态判定建议

```text
内核未运行
→ 默认状态

内核运行，但连接测试、出口测试或可用性测试连续失败
→ 红色异常状态

连接正常，并且当前线路类型为机场订阅
→ 紫色状态

连接正常，并且当前线路类型为独享代理或静态代理
→ 绿色状态
```

建议增加防抖机制：

```text
连续失败 3 次后切换为异常状态
连续成功 2 次后恢复正常状态
```

检测中可以使用轻微呼吸动画或“检测中”角标，但不要再增加过多永久状态颜色。

## 3.4 图标应用位置

状态图标需要统一应用到：

- Windows 系统托盘；
- 软件窗口标题栏；
- Windows 任务栏；
- 软件左上角品牌区域；
- 软件内部连接状态卡片。

所有位置必须由统一的状态管理模块控制，禁止每个组件自行判断颜色。

# 4. 运行概览新增信息

运行概览应成为只读监控面板，主要回答：

1. 当前是否已连接；
2. 当前使用哪种线路；
3. 当前使用哪个节点；
4. 当前出口 IP 和国家是什么；
5. 当前实时上传下载速度是多少；
6. 最近 60 秒网络变化如何；
7. 当前 IP 的风险和纯净度如何；
8. 当前内核、接管模式和连接数是什么。

---

## 4.1 入口 IP 与出口 IP 检测

页面中建议不要仅使用“入口 IP”这个词，避免歧义。

建议展示：

### 直连公网 IP

表示不经过代理时，本机网络的公网 IP。

显示字段：

- IP 地址；
- 国家和地区；
- 国旗；
- ISP；
- ASN；
- 网络类型；
- 检测时间；
- 检测结果来源。

### 代理出口 IP

表示经过当前代理线路后的出口 IP。

显示字段：

- IP 地址；
- 国家和地区；
- 国旗；
- ISP；
- ASN；
- 网络类型；
- 当前节点；
- 检测时间；
- 检测结果来源。

### 检测要求

- 直连 IP 必须强制通过 Direct Outbound 请求；
- 出口 IP 必须强制通过当前代理 Outbound 请求；
- 两条检测链路不能混用；
- 至少支持两个检测服务，主服务失败后自动切换；
- 直连 IP 和出口 IP 相同时，提示“代理可能未生效”；
- 检测失败时必须明确区分：
  - DNS 失败；
  - TCP 连接失败；
  - TLS 失败；
  - 请求超时；
  - 服务端返回异常；
  - IP 数据解析失败。

---

## 4.2 当前节点实时上传下载速度

运行概览新增实时速度信息：

- 当前下载速度；
- 当前上传速度；
- 本次运行累计下载；
- 本次运行累计上传；
- 当前活动连接数；
- 当前节点延迟；
- 当前节点名称；
- 当前线路来源；
- 当前接管模式。

建议展示示例：

```text
下载速度：12.8 MB/s
上传速度：1.6 MB/s
累计下载：128.4 MB
累计上传：18.7 MB
活动连接：36
节点延迟：82 ms
```

单位需要自动切换：

```text
B/s
KB/s
MB/s
GB/s
```

不要直接在 UI 层分别读取 sing-box、Mihomo、Xray 的不同接口。

应增加统一数据适配层：

```text
CoreMetricsAdapter
├── SingBoxMetricsAdapter
├── MihomoMetricsAdapter
└── XrayMetricsAdapter
```

统一向 UI 输出：

```text
timestamp
uploadBytesPerSecond
downloadBytesPerSecond
totalUploadBytes
totalDownloadBytes
activeConnections
latency
coreName
nodeName
sourceType
captureMode
```

## 4.3 最近 60 秒流量图

新增当前节点最近 60 秒流量监控图。

### 采样规则

- 每 2 秒采样一次；
- 展示最近 60 秒；
- 固定保存 30 个数据点；
- 使用 Ring Buffer；
- 默认只保存在内存中；
- 不需要每 2 秒写入数据库。

### 图表类型

支持在以下两种形式之间切换：

#### 折线图

展示：

- 下载速度曲线；
- 上传速度曲线；
- 时间轴；
- 当前值；
- 峰值；
- 平均值。

#### 柱状图

展示：

- 每 2 秒实际上传的数据量；
- 每 2 秒实际下载的数据量。

### 交互要求

- 鼠标悬停显示时间、上传值、下载值；
- 自动切换单位；
- 图表宽度变化时自适应；
- 节点切换后清空或明确分隔旧数据；
- 代理断开后保留最后一段数据，但标记已停止；
- 不允许图表持续无限积累前端对象；
- 页面隐藏后应降低无意义重绘，但数据采集是否继续由业务层决定。

运行概览只展示 60 秒简版。

单独的“流量监控”页面可扩展：

- 60 秒；
- 5 分钟；
- 1 小时；
- 本次运行；
- 按节点统计；
- 按线路来源统计。

# 5. IP 纯净度与风险检测

## 5.1 不要把“纯净度”做成单一且不可解释的分数

IP 纯净度没有完全统一的行业标准。

其他平台通常会展示：

- Fraud Score；
- Proxy；
- VPN；
- Tor；
- Hosting；
- Data Center；
- Residential；
- ISP；
- ASN；
- Usage Type；
- Abuse；
- Blacklist；
- Threat；
- Bot；
- Recent Abuse；
- Country Consistency；
- Location Consistency；
- Provider；
- Last Seen；
- Public Proxy；
- Shared Proxy；
- Anonymous Proxy。

Navo 应将“纯净度”理解为一组风险指标的综合展示，而不是仅显示一个百分比。

## 5.2 建议展示字段

```text
综合纯净度：86 / 100
风险等级：低风险

网络属性：住宅 / ISP / 机房 / 移动网络
代理类型：住宅代理 / 数据中心代理 / VPN / Tor / 未识别
欺诈风险：12 / 100
滥用记录：未发现
黑名单状态：未发现
VPN：否
Tor：否
数据中心：否
机器人风险：低
ASN：AS12345
ISP：Example Broadband
国家一致性：正常
时区一致性：正常
最近代理记录：7 天前
检测时间：2026-xx-xx xx:xx:xx
数据来源：具体服务名称
```

## 5.3 评分建议

可以将综合评分拆成以下维度：

| 维度 | 建议权重 |
|---|---:|
| 欺诈、滥用、黑名单记录 | 40% |
| 网络属性和住宅属性 | 25% |
| VPN、Tor、公共代理识别 | 20% |
| 国家、ASN、时区和地理一致性 | 15% |

但必须满足：

- 分数算法可解释；
- 页面可以查看各维度扣分原因；
- 不允许只显示“纯净”或“不纯净”；
- 多个检测源结果冲突时，要直接展示冲突；
- 不允许宣传能够绝对判断 IP 是否独享；
- 不允许声称能够准确知道当前有多少人共用同一个 IP；
- 必须显示检测来源和检测时间；
- 第三方接口失败时，不影响基础代理连接。

## 5.4 多来源结果示例

```text
IPQS：低风险
Scamalytics：中风险
IP2Proxy：住宅代理
```

不要静默取平均值后隐藏差异。

## 6.3 连接管理

连接管理负责实际连接配置。

建议包含：

```text

├── 机场订阅
└── 独享代理 / 静态代理

节点选择
接管模式
├── 不接管
├── 系统代理
└── TUN

连接
断开
重连
连接前检测
```

默认应根据：

- 协议支持；
- 当前节点类型；
- 接管模式；
- 内核可用性；
- 用户默认设置；

自动选择合适内核。

手动指定内核放在高级设置中。

```text

```

建议状态示例：

```text

├── stopped
├── starting
├── running
├── stopping
└── failed

ConnectionState
├── disconnected
├── connecting
├── connected
├── reconnecting

NetworkHealthState
├── unknown
├── checking
├── healthy
├── degraded
└── unavailable

├── airport
```

图标状态必须由统一规则派生：

```text
IconState = derive(
```

- 托盘单独判断；
- 主窗口单独判断；
- 标题栏单独判断；
- 各组件直接读取内核进程后自行变色。

# 9. 数据采集与性能要求

## 9.1 采样

- 每 2 秒采集一次实时指标；
- 60 秒窗口保存 30 个点；
- 使用固定容量 Ring Buffer；
- 不允许数组无限增长；
- 不允许每次采样触发整个页面重建；
- 图表只更新必要的数据；
- 页面最小化时降低绘制开销；
- 数据采集与 UI 渲染解耦。

## 9.2 错误处理

以下错误必须区分：

- 内核未启动；
- 内核启动失败；
- API 不可用；
- 节点不可连接；
- DNS 异常；
- 出口检测失败；
- IP 检测服务失败；
- 纯净度服务失败；
- 图表数据暂不可用；
- TUN 不可用；
- 系统代理设置失败。

不能统一显示“连接失败”。

## 9.3 降级策略

- IP 纯净度接口失败，不影响代理连接；
- 某个 IP 检测服务失败，自动切换备用服务；
- 某个内核不支持流量统计时，显示能力缺失；
- 当前节点不支持某些指标时，不伪造数据；
- 图表无数据时显示空状态；
- 不允许使用测试数据冒充真实数据。
